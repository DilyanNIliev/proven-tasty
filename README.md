# Доказано Вкусно

Сайт с рецепти. Построен е така, че **нова рецепта се добавя на едно място** и сама се появява
навсякъде — в менютата, в „Всички рецепти“, в търсачката, в пазарския списък и в Google.

---

## Как е устроено

```
data/recipes.json      ← ЕДИНСТВЕНОТО място с рецептите (източник на истината)
data/articles.json     ← статиите в „Полезно“
data/site.json         ← име на сайта, меню, категории, AdSense, Google Analytics

content/*.html         ← текстовото съдържание на всяка страница (без меню и футър)
assets/site.css        ← целият дизайн на сайта — на едно място
assets/site.js         ← целият JavaScript — на едно място
assets/recipes-data.js ← генерира се автоматично, НЕ се пипа

tools/build.mjs        ← генераторът, който прави HTML страниците
admin.html             ← форма за добавяне на рецепта директно от браузъра

*.html (в корена)      ← ГЕНЕРИРАНИ страници, не ги променяй на ръка
images/recipes/        ← снимките на рецептите
```

Ключовото: **всички `.html` файлове в корена се генерират.** Ако ги промениш на ръка,
промяната изчезва при следващото генериране. Дизайнът се променя в `assets/site.css`,
текстовете — в `content/`, рецептите — в `data/recipes.json`.

---

## Как се добавя нова рецепта

### Начин 1 — през формата в сайта (най-бърз)

1. Отвори `admin.html` (например `https://твоят-сайт.bg/admin.html`).
2. Попълни: заглавие, кратко описание, снимка, категории, време, порции, съставки, стъпки.
   - Снимката просто я провлачваш — сама се смалява и компресира.
   - За съставките има поле **„Бърз начин“** — поставяш целия списък наведнъж,
     по една съставка на ред, и програмата сама разделя количество / мярка / продукт.
3. Натискаш **„Публикувай в GitHub“** → рецептата се записва и след около минута е на живо.

За да работи публикуването, веднъж попълваш в „Настройки за GitHub“:
потребител, хранилище, клон и токен. Токенът се създава от
GitHub → Settings → Developer settings → **Fine-grained tokens**, само за това
хранилище, с права **Contents: Read and write**. Пази се само в твоя браузър.

Ако не искаш да ползваш токен: натисни **„Изтегли recipes.json“**, сложи файла в папка
`data/`, а снимката в `images/recipes/`, и качи промените в GitHub.

### Начин 2 — казваш ми данните

Пращаш ми заглавие, описание, съставки, стъпки, време, порции и снимка — добавям ги аз.

### Начин 3 — на ръка

Добавяш обект в `data/recipes.json` и пускаш:

```bash
node tools/build.mjs
```

## Полета на една рецепта

| Поле | Какво е | Задължително |
|---|---|---|
| `id` | уникален код без интервали (напр. `pileshko`) | да |
| `slug` | адресът на страницата → `recipe-<slug>.html` | да |
| `title` | пълното заглавие | да |
| `cardTitle` | по-кратко заглавие за картичките | не |
| `excerpt` | едно изречение за картичката и Google | да |
| `lead` | уводният текст на страницата | не |
| `meal` | `breakfast` / `lunch` / `dinner` / `salad` / `dessert` — за филтъра | да |
| `categories` | в кои менюта излиза: `mains`, `breakfast`, `desserts`, `salads`, `athletes` | да |
| `badge` | етикетът върху снимката | не |
| `time` | време в минути (число) | да |
| `servings`, `kcal`, `protein` | порции, калории, протеин | `servings` |
| `image`, `hero`, `imageAlt` | снимки и описание на снимката | да |
| `keywords` | думи за търсачката в сайта | не |
| `ingredients` | списък: `{text, name, amount, unit}` или `{section}` за подзаглавие | да |
| `steps` | списък от стъпки | да |
| `note` | кратка бележка накрая | не |
| `why` | списък `{h, p}` — секцията „Защо си заслужава“ | не |
| `date` | дата — определя подредбата (най-новите първи) | да |
| `published` | сложи `false`, за да скриеш рецепта, без да я триеш | не |

`amount` и `unit` се използват за автоматичния пазарски списък — затова
`{"text": "2 глави лук", "name": "лук", "amount": 2, "unit": "глави"}`.

## Команди

```bash
node tools/build.mjs        # генерира целия сайт
python3 -m http.server 8000 # преглед на http://localhost:8000
```

При качване в GitHub генерирането се случва и само — виж
`.github/workflows/build.yml`.

---

## Еднократна настройка на GitHub Pages

**Задължително след сливането на този клон:** влез в хранилището →
**Settings → Pages → Build and deployment → Source** и избери **GitHub Actions**
(вместо „Deploy from a branch“).

Защо: когато сайтът се раздава направо от клон, GitHub не пуска ново качване след
промените, направени автоматично от Actions. Резултатът е, че рецептата се записва,
страниците се генерират, но сайтът остава стар. С „GitHub Actions“ генерирането и
качването са една операция и живият сайт винаги отговаря на данните.

Работният процес качва всичко без `tools/`, `content/` и `.github/` — тоест самият
сайт плюс `data/` (нужна е на `admin.html`, за да показва съществуващите рецепти).

Ако не искаш формата за добавяне да е достъпна публично, добави
`--exclude 'admin.html'` към стъпката „Подготви файловете за качване“ в
`.github/workflows/build.yml` и я ползвай само локално.

## Преди пускането на живо

1. В `data/site.json` смени `url` с истинския домейн — от него зависят
   `sitemap.xml`, каноничните адреси и как сайтът изглежда при споделяне.
2. За реклами: сложи номера от AdSense в `adsenseClient` (напр. `ca-pub-1234567890`).
   Рекламните места се появяват автоматично; докато полето е празно, няма никакви реклами.
3. За статистика: сложи `gaMeasurementId` (напр. `G-XXXXXXX`).
4. Пусни `node tools/build.mjs` и качи промените.
5. Подай `sitemap.xml` в Google Search Console.

Всяка страница на рецепта вече съдържа structured data (`Recipe`), затова Google
може да я показва със снимка, време за приготвяне и калории в резултатите.
